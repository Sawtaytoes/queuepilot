| 2026-08-14 | [A weight is SLOTS PER ROUND, not odds](2026-08-14-weights-are-slots-per-round-not-odds.md) *(feature / playback semantics — any entry a randomized set draws from can carry `weight: 1-20`, meaning how many slots it takes per round; 1 is never stored. Three carriers, each written like its neighbour: a queue entry's own key, a member mapping's key, and a channel's `weights: {ratingKey: n}` map (the mirror of `starts`). Slots not odds because a rotation exists so consecutive items are DIFFERENT shows — a 3/1/1 die deals the same show three times running, which is what the round-robin was built to prevent. Smooth weighted round-robin (nginx's): 3/1/1 deals A B A C A. Two exceptions where a weight is odds: a curated CHANNEL (plays each member once, so a weighted shuffle) and the rewatch card (one film, so it multiplies the 1/n² bias). **Also fixes:** `nextQueue` only shuffles when handed an rng and the provider never handed it one — every curated channel had played in file order since the Python retirement)* |
